## Gaps

### Parquet file sink (local Parquet write)
- Earlier files: komira_parquet/parquet_sink.mojo, komira_parquet/streaming_parquet_writer.mojo (and file output side of parquet_parallel_writer.mojo)
- Missing: a Sink that writes batches to a .parquet file at a path, with compression, row-group size and dictionary options, row-group coalescing, bounded memory, footer written at finish, and removal of the partial file on error. Current src/parquet_writer returns bytes only and opens no file; src/scan_source/sink.mojo defines the Sink trait but no Parquet sink exists; src/sdk_exec runs a COPY to a local Parquet file by encoding the whole result with src/parquet_writer and writing it with fs.atomic_write.write_file_atomic (a temporary file renamed over the destination), not through a streaming sink; CREATE TABLE AS is refused by name.
- Why: df.write_parquet and writing a query result to Parquet are core local-SDK operations.
- Task: pysdk-engine-write-parquet

### Glob, multi-file and Hive Parquet scans in the SQL path
- Earlier files: komira_parquet/materialize_parquet.mojo
- Served: register_parquet takes a file, a glob or a directory; read_parquet('<glob>') in SQL expands a glob; Hive key=value directories become partition columns (DATE, TIMESTAMP, BIGINT or VARCHAR), and a filter on one prunes files. Row order across files is not promised. Refused by name: PARQUET_GLOB_NO_MATCH, PARQUET_PATH_IS_DIRECTORY, PARQUET_FILES_SCHEMA_MISMATCH, HIVE_PARTITION_LAYOUT_MISMATCH, HIVE_PARTITION_VALUE_UNSUPPORTED (including NULL partitions), HIVE_PARTITION_COLUMN_IN_FILE. Still refused by lowering: the lazy Hive shapes (LOWERING_SCAN_NOT_TOTAL).
- Task: pysdk-engine-multifile-scan (Parquet part done)

### CSV and NDJSON sources in the SQL and DataFrame path
- Earlier files: komira_parquet/csv_reader.mojo
- Done for one local CSV file, with or without a header row (without one the columns are column0, column1, ... as DuckDB names them): read_csv lowers to a SOURCE_CSV segment and src/pipeline_exec/source_csv.mojo decodes it at the bound types (plain or .gz, .zst, .lz4); src/sdk_exec/tests/test_run_sql_csv.mojo holds it to DuckDB. Missing: NDJSON, a CSV glob or several files, and a CSV registered as a table (src/sdk_exec only has register_parquet). Closest code: src/scan_source/csv_source.mojo, json_source.mojo and src/pipeline_exec/source_batch.mojo.
- Why: the SDK must run SQL over CSV and NDJSON files, not only Parquet.
- Task: pysdk-engine-csv-source

### Extended aggregates (CORR, MEDIAN and kin) in pipeline_exec
- Earlier files: komira_parquet/materialize_parquet_extended_agg_sink.mojo
- Missing: pipeline_exec ungrouped and grouped sinks serve SUM, COUNT, COUNT(*), MIN, MAX, AVG and COUNT(DISTINCT) only. Closest code is src/op_agg_slab (SlabHashAggSinkStructCorr), not wired to lowering. The earlier LARGEST_K itself is a benchmark shape and is dropped; the DuckDB-equal functions (corr, median and similar) are what is needed.
- Why: SQL function breadth equal to DuckDB for data-analysis queries.
- Task: pysdk-engine-extended-aggregates
