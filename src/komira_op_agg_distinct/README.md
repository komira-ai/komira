# komira_op_agg_distinct

The COUNT(DISTINCT) kernels of grouped aggregation. This part holds the streaming COUNT(DISTINCT) sink, the stage DISTINCT state, and the kernels the sink and the grouped COUNT(DISTINCT) driver build on; that driver is added by a later change.

- `agg_count_distinct_strenc`: the STRING / LARGE_STRING group-key encode. A parallel pass hashes every row (FNV-1a 64 plus a length mix); dict ids are then assigned in FIRST-SEEN row order, verifying every hash hit against the bytes, by the first of three bodies that serves the key: one dictionary per row range merged in row order (`agg_cd_strenc_rowdict`, for keys with few distinct values), one dictionary per hash shard merged in parallel with the numbering preserved (`agg_cd_strenc_parb`, for at least 1,048,576 rows), or a serial open-addressed table. The first two leave the reverse map pointing into the source column's value buffer; the serial one builds an arena.
- `agg_cd_dictkey_encode`: `encode_dict_key_first_seen`, the same first-seen numbering for a DICTIONARY key column, by value (a dictionary that stores a value twice still yields one id), reading the column's window; a code past the dictionary raises.
- `agg_cd_distinct_set`: `CdDistinctSet`, the per-worker open-addressed set of (aggregate slot, group, value) pairs probed at insert; `admit` is True once per distinct pair.
- `agg_cd_heavy_split`: the heavy-group split. `cd_split_groups` and `cd_heavy_groups` pick, from a sample of group hashes, the groups whose share passes 1/(4K) or 2/K; `cd_pair_bucket` assigns a pair of such a group to a worker by (group, value).
- `agg_cd_group_ht_sizing`: the first size of a worker's group table, from an upper bound on the groups (the product of the key dictionaries' sizes plus NULL, capped at the rows) rather than from the rows.
- `agg_cd_key_emit`: `cd_emit_string_key_column`, which turns the output groups' dict ids into the STRING key column, for every group or for a bounded list of them.
- `cd_radix_parallel`: `radix_distinct_count` / `radix_distinct_count_multi`, the exact COUNT(DISTINCT) of one or several Int64 buffers: the values are partitioned by a value hash, each partition is deduped in parallel, and the counts are summed (equal values share a partition, so nothing is counted twice). `CdRadixOptions` picks the arm (a serial scatter below 125,000 values, a parallel scatter into L2-sized partitions above) and how buffers are freed; every setting returns the same count.
- `cd_radix_grouped`: `radix_distinct_count_grouped`, the same count for every group of a grouped drain, parallel across groups: big groups are split into value-hash sub-cells and every cell is one task.
- `cd_string_parallel`: `count_distinct_string_column`, the exact COUNT(DISTINCT) of a STRING / LARGE_STRING column (NULLs excluded) without materializing a value: rows are hashed in place, a per-task duplicate pre-filter drops proven repeats, packed (fingerprint, row) entries are scattered by hash and each partition is deduped with a byte-compare verify; `count_distinct_string_column_serial` is the serial arm by name. Any other column type raises.
- `streaming_agg_count_distinct`: `WorkerCDState`, the per-worker state of the streaming COUNT(DISTINCT) aggregation. Grouped, each row's key resolves to a group id (through a dense window when the key domain spans at most 65,536 keys, else a Dict with a one-entry last-key memo) and each value is appended to its (aggregate, group) cell unless it equals the cell's last value; fixed aggregates (SUM, COUNT, MIN, MAX, AVG) of a mixed query fold against the same group id, on a separate instantiation of the row loop. Ungrouped, values are deduped during the scan into per-partition hash sets. Its row loop is in `cd_stream_consume`. Each mechanism has a switch field (default: on, except scan-time dedup of a cell) and a counter, so a test can compare both arms and see which ran.
- `agg_sink_count_distinct`: `CountDistinctAggSink`, the `komira_operator_api.MorselSink` of an aggregate whose COUNT(DISTINCT)s are grouped by at most one INT32 / INT64 key, optionally mixed with SUM, COUNT, MIN, MAX and AVG. `consume` applies the segment's filters and folds a batch into the worker's `WorkerCDState`; `combine` collects the workers; `finalize` emits the batch: ungrouped, the union of the workers' per-partition dedup sets (`agg_count_distinct_kernel`); grouped, one global group directory, the value buffers moved into `radix_distinct_count_grouped`, and the fixed aggregates merged (MIN and MAX in DuckDB's order, NaN largest). A NULL key is one group whose key reads back as NULL.
- `cd_global_dir`: `CdGlobalDir`, the map from every worker's group ids onto one global numbering in first-seen order, built once per finalize.
- `cd_passenger_lane_counter`: process-wide counters of the grouped batches consumed and of those that ran the fixed-aggregate lane.
- `distinct_state`: `DistinctState[*Keys]`, the stage DISTINCT breaker state: rows are deduped by their key columns (`distinct_key_column`: `DistinctKeyColumn_Typed[dt, col]`; `distinct_key_column_string`: `DistinctKeyColumn_String[col]`) through an open-addressing directory over a first-seen row index, and drained once each, in first-seen order. Float keys compare as DuckDB's DISTINCT does: every NaN is one value, and `-0.0` equals `0.0`. States combine across workers, and spill to and restore from a `komira_engine_runtime` spill storage as THSPLC chunks. The key domain is fixed-width numeric and STRING keys with no NULLs: the state stores values and no validity, so `feed_row` raises on a NULL key. A state that still holds spilled rows raises from `drain_to_record_batch` and refuses to be the argument of `combine` until `restore_from_storage` has run.
- `median_parallel_drain`: `parallel_group_finalize_column`, which finalizes each occupied group of an aggregate (the stage MEDIAN drain) and appends the output column, fanning the groups out over the dispatcher's workers from 256 groups up; the column is the same either way.

The numbering of the string encode is the driver's output group order, so every body must number identically; the tests hold each parallel body to the serial one. The `cd_*_count` / `reset_*` functions are process-wide counters that let a test see which route ran. The encode entry points take the raw value and offset buffers of a column and are package-private.
