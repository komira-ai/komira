## The cases of the Connect conformance run (conformance.yaml, the suite
## pinned in third_party/connect-conformance) that komira_connect fails, as
## the runner's `--known-failing` patterns: `*` is one name component, `**`
## any number. The runner fails the run when a listed case passes or a
## pattern matches no case, so the list only shrinks. Each block is one
## reason (the `#` lines, checked by known_failing.mojo) and the patterns
## it covers. A case name is
##   <suite>/HTTPVersion:2[/Protocol:<p>][/Codec:..][/Compression:..]/TLS:true/<test>
## where the Protocol, Codec and Compression components appear only for a
## suite that applies to more than one of them.

# An unsupported Content-Type is answered HTTP 404: the request is not
# routed to the service at all (the HttpServer's router has no route for
# it), so the client reads UNIMPLEMENTED; the suite expects the request
# refused as an unsupported media type (HTTP 415, read as UNKNOWN).
Connect Unexpected Requests/**/unexpected-codec
Unexpected Requests/**/unexpected-content-type

# A malformed request body is always UNKNOWN: when decoding the request
# fails, komira_connect's dispatch (dispatch.mojo, the decode `except`) and
# its streaming path (service.mojo, dispatch_grpc_stream's decode `except`)
# return GRPC_STATUS_UNKNOWN with the decoder's text as the message, so the
# `[grpc:13]` / `[grpc:12]` code the gRPC decoder names is dropped (and
# shows up in grpc-message); the gRPC-Web decoder's errors
# (codec_grpc_web.mojo) carry no code, and an empty gRPC-Web body is
# answered UNKNOWN directly. The suite expects UNIMPLEMENTED for a unary call
# with no or several request messages and INTERNAL for a compressed message
# on a call that negotiated no compression.
gRPC Unexpected Requests/**/unary/multiple-requests
gRPC Unexpected Requests/**/unary/no-request
gRPC Unexpected Requests/**/unexpected-compressed-message
gRPC-Web Unexpected Requests/**/unary/no-request
gRPC-Web Unexpected Requests/**/unexpected-compressed-message
