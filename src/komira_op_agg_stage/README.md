# komira_op_agg_stage

The stage hash aggregation: `HashAggTable[KB, *Aggs]`, the HASH_AGG breaker state (`komira_operator_api.BreakerStateCombinable`). One variadic struct covers every GROUP BY key arity and aggregate pack.

- `key_block`: the GROUP BY key block. `KeyTupleScalar` is the one group of an ungrouped aggregate; `AggKeyBlock[*Keys]` holds one or more key columns (`komira_op_agg_distinct` `DistinctKeyColumn_Typed[dt, col]` / `DistinctKeyColumn_String[col]`) behind a growable open-addressing directory over an FNV-1a composite hash, numbering groups 0, 1, 2, ... in first-seen order, with no cap on the group count. A NULL key is one key value: rows group together by their NULL pattern and non-NULL keys, and the key reads back NULL. `KeyTuple1` / `KeyTuple2` / `KeyTuple3` name the numeric-key blocks of one to three keys.
- `agg_column`: `AggColumn`, one aggregate with one state per group, and `AggSlot[A]` over a `komira_agg.Aggregator`. A row whose input is NULL (`A.input_is_null`) is not folded as a value (FIRST / LAST pick it, as DuckDB's do); a group with no non-NULL value answers NULL, except COUNT and COUNT(DISTINCT), which answer 0 (`A.EMPTY_IS_NULL`). An integer SUM is exact and narrowed to INT64 at emission; a total outside INT64 raises `komira_op_agg_state.int_sum_overflow_message`. `AggBlock` carries the aggregate pack into the table's constructor.
- `agg_fn_slot`: `AggFnSlot[F, col]`, a user-defined `komira_udf.AggFn` over one input column as an aggregate column: NULL inputs are skipped and an empty group answers `finalize(init())`, as `komira_op_agg_state.AggFnAcc` does.
- `hash_agg`: `HashAggTable`. `feed_row` folds a row; `feed_chunk_global` / `fold_scalar_view` are the ungrouped masked folds; `consume_band` folds a decoded `komira_arrow.BandView` without a RecordBatch. `combine` merges another worker's table by key value; `combine_move_distinct` moves COUNT(DISTINCT) value buffers instead of copying them; `combine_partition_from` merges the groups of one hash partition, for a parallel combine fanned out by `n_combine_partitions` (`with_radix_min_groups` sets its threshold). `drain_to_record_batch` emits one row per group (an ungrouped aggregate: exactly one row, also over no input); `drain_to_record_batch_parallel` counts COUNT(DISTINCT) and finalizes MEDIAN on the dispatcher's workers, with the same result. The drain-at-offset surface (`emit_at_offset_plan` / `_data_bytes` / `_write`) writes one partition straight into shared output columns; those carry no validity, so a column holding a NULL is ineligible and a write that meets one raises.

`waiting_tests.tsv` lists the tests of this code that move with packages not ported yet.
