# Committed generated sources

A library generated by `mojo_aws_client`, `mojo_gcp_client`,
`mojo_proto_library` or `mojo_db_proto_library` is built from one place: the
directory `generated/<name>/` of its package, committed to the repository.
Nothing else is a source of the library. The generator still runs, in a check.

```text
src/komira_aws_sqs/
  BUCK
  generated/komira_aws_sqs/      what the generator wrote; the library's sources
    __init__.mojo
    komira_aws_sqs.mojo
    _layout_probe.mojo           (aws and gcp clients) the library's first test
```

For a library `<name>` the rule declares three targets:

| target | what it is |
|---|---|
| `<name>_gen` | the generator's output for the current inputs. Nothing is compiled from it. |
| `<name>_fresh` | regenerates, compares with `generated/<name>/`, file by file and byte by byte, and fails with the command that regenerates. |
| `<name>` | a `mojo_library` over `generated/<name>/`. `<name>_fresh` is its first gate: a hidden input of the compile, so no `.mojoc` exists and no test of the library is built while the committed files are not what the generator writes now. |

`<name>_fresh` is the only reader of `<name>_gen`. A package of the library's
`test_data` that reads the generated files (the environment scans) reads the
committed ones.

## When it goes red

The check fails for each of these, and its message says which:

- a committed file was edited by hand (`differs`: the first line that differs,
  both sides);
- a file the generator writes is not committed (`missing`);
- a committed file is no longer generated (`stale`);
- a model, a `.proto`, an attribute of the rule, the generator or a hand-written
  source it copies changed, and the commit was not regenerated (`differs`,
  `missing` or `stale`, depending on what moved).

The message ends with the command:

```text
./buck2 run komira//tools/build/gen:regen -- komira//src/komira_aws_sqs:komira_aws_sqs
```

## Regenerating

```sh
./buck2 run komira//tools/build/gen:regen -- <library target>...    # libraries
./buck2 run komira//tools/build/gen:regen -- komira//src/x:          # every generated library of a package
./buck2 run komira//tools/build/gen:regen -- all                     # every one of the cell `komira`
```

`regen` asks buck2 for the `<name>_fresh` targets, builds their `<name>_gen`
targets in one build (on the farm, as the checkout is configured), and makes each
committed directory equal to the output: a file that differs is written, a file
the generator no longer writes is removed, an equal file is not touched. The
files are written sorted, with mode 0644 and no timestamp of its own, so a
second run changes nothing. Commit the directory with the change that needed it.
A generator change lands with the regeneration of every library it touches, in
one commit.

The header of every generated file says the same (`header.rs`, and the
`__init__.mojo` text of `aws_act.zig` and `proto_gen.zig`);
`:command_agreement` holds the four spellings equal.

A library whose `_gen` has no committed directory yet, and is not in the ledger
below, is a target that fails at analysis with that command: this is the state a
new generated library starts in, and the one `regen` takes it out of.

## Transition

A library that is built from the generator, as every one was before this
directory, is listed in [`transition.bzl`](transition.bzl). This is a switch
with an end, not a second way to build: the list only shrinks, and when it is
empty the code that builds from `<name>_gen` is deleted.

- A listed library has no `<name>_fresh` and no `generated/<name>/`.
- Migrating one is a commit: delete its line, run `regen` on it, commit the
  directory. A line left behind for a library that has a committed directory is
  an error at load, so the list never says what is not true.
- `:transition` writes the list as a file, and `:transition_lint` holds it
  sorted, free of duplicates, and no longer than the count in its BUCK entry,
  which only goes down. It prints every library still on the list when it runs.

## Layout and limits

- The directory is flat in practice (every generator writes one directory of
  modules); a subdirectory is carried and compared like any file.
- A mojo_aws_client's `hand_srcs` are copied into the generated directory by the
  generator, as before, and so are committed there; `regen` keeps the copy equal
  to the hand-written source, and `_fresh` fails when the source is edited and
  the directory is not regenerated.
- The first line of every generated file carries `@generated` (see
  [`header.rs`](../proto-codegen/src/header.rs)); a tool that must tell a
  generated file from a written one matches it there.
